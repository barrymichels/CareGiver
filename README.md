## Key Features

### For Staff Members
- Set and update your availability with an interactive calendar
- Export your schedule to your preferred calendar app
- Get notifications for schedule conflicts
- Save default availability preferences

### For Administrators
- Easily assign staff to shifts with conflict detection
- Manage user accounts and permissions
- Monitor schedule coverage and conflicts
- Batch assign shifts with automatic validation
- Create and manage virtual users for non-tech-savvy staff
  - Add virtual users with just a name
  - Manage their availability directly
  - Convert virtual users to regular users when needed

## Quick Start

### Manage schedule templates

Open **Schedule Templates** from the admin menu. Choose a template from the list
and edit its daily timeslots. **Save changes** updates that same template.
Create a template, rename it, duplicate it, make it the default, or delete it from
this page. Each day is independent; **Copy to All Days** and **Copy to selected
days** speed up repeated schedules. Unsaved changes stay in a draft until saved.
Deleting the default requires choosing a replacement.

### Choose a schedule for a week

In the **Admin Panel**, navigate to the desired Monday–Sunday week and click
**Change template**, select a template, and **Apply to this week**. Weeks can be
configured up to eight weeks ahead. Past weeks remain locked.

Unconfigured weeks start with the current default. **Make default** also replaces
current and future weeks that have no saved availability or assignments, even
if another template was selected for them. **Update empty weeks** on the current
default applies the same rule without switching defaults. Past weeks never change.

Weeks with saved availability (including unavailable responses) or assignments
stay unchanged and are listed for review. To change one, use **Change template**
in the Admin Panel. Entries at unchanged times remain intact; the app lists any
entries at removed times and requires approval before clearing them. Editing a
template alone does not apply its changes to weeks. Deleting the default requires
a replacement, which follows the same empty-week update rule.

The template management design was selected through interactive prototypes.
The reviewed alternatives are preserved on branch `prototype/template-management`
(commit `fcd6f676`); round-two B was selected: compact template list, action header,
and the original day editor. Run `npm run prototype:templates` on that branch to
revisit the prototypes.

### Run locally

1. Install dependencies:
```bash
npm install
```

2. Set up environment:
- Copy `.env.sample` to `.env`
- Update required settings

3. Start the app:
```bash
npm start
```

For development:
```bash
npm run dev
```

## Technical Details

- **Stack**: Node.js, Express, SQLite3, EJS templates
- **Security**: bcrypt password hashing, secure sessions, SQL injection prevention
- **Testing**: Jest with Supertest (`npm test`)

## Database Schema

### Core Tables
- Users (id, name, email, role)

- Assignments (user_id, date, time_slot)
